# Verification & economy-measurement research — papers and repos to mine

Scope: LLM-as-judge reliability (the mechanism behind `core/verify.py`'s
`reviewer_verdict`), agentic code review, regression/predictive test selection
(for `economy/testselect.py`), false-green and reward-hacking detection (tests
that pass without verifying — AGENTS.md rule 8), cost-aware agent benchmarks,
flaky-test detection, provider health/dead-model prior art (for
`gateway/dead_models.py`), and savings-attribution methodology (for
`economy/savings.py`'s `SavingsProof`). Every row below was fetched and read,
not guessed from a title. The honest picture: ForgeOS's existing
`testselect.py` (escalate-on-unknown, never a silent empty selection) and
`savings.py` (provenance-weakest-wins) already implement the *conclusions*
several of these papers spent years reaching empirically — the value here is
mostly external validation and the specific numbers/mechanisms to cite, plus
one genuinely new and urgent gap: nothing in ForgeOS currently detects an
agent gaming its own verification ladder.

| [SpecBench](https://arxiv.org/html/2605.21384) (arXiv 2605.21384) | paper | Coding-agent reward-hacking benchmark: a visible validation suite (what the agent optimizes against) vs. a hidden held-out suite (feature *compositions*, simulating real use). Reward-hacking gap = validation pass rate − held-out pass rate. ## Top 5 actions (novelty × demand ÷ effort)

1. **Add a reward-hacking / test-tampering gate to the merge path, per SpecBench and the RLVR-gaming survey.** This is the one genuine gap: `testselect.py` decides which tests run but nothing currently checks whether the diff being verified also modified the tests or assertions it's supposed to be verified by. A deterministic, non-LLM check — flag any changeset that edits a test file and its corresponding source in the same commit for mandatory INTEGRATION-rung escalation — is cheap and closes a real hole the "false green" rule (AGENTS.md #8) doesn't currently cover.
2. **Cite Panickssery et al. and the position-bias study directly in `core/verify.py`'s docstring, and harden `reviewer_verdict` production.** The self-review block (`reviewer_worker == implementer_worker` and substring-decoration check) already exists and is exactly right — it just isn't yet connected to *why* it's right, or extended to require a different provider family (per the self-preference mitigation paper) when `reviewer_verdict` comes from a model call rather than a human.
3. **Add DeFlaker-style coverage-diffing before the governor spends a retry escalating a failure.** Zero rerun cost, cheap to implement (ForgeOS already runs coverage-aware test selection), and directly protects the budget: a test that failed without touching any changed line is very likely flaky, not a regression, and shouldn't burn an escalation.
4. **Study `hal-harness`'s design before building `tools/ab_bench.py` into the public leaderboard ROADMAP §3 wants.** HAL already solved the exact problem stated there (accuracy-only benchmarks hide cost) at real scale (21,730 rollouts, full public transcripts) — cloning the harness design, not the leaderboard itself, saves reinventing the orchestration-and-publication plumbing.
5. **Add a background health-prober to `gateway/dead_models.py` (the "Fleet doctor" ROADMAP item).** The circuit-breaker literature's half-open-probe pattern is a small, well-understood addition: recover a temporarily-dead model automatically on a timer instead of only re-testing it the next time a real job happens to route there.
